# Provider profiles

Store public, reviewed transport settings here. `offline.yaml` selects a fake; `openrouter.yaml` and `gemini.yaml` select the shared chat-completions adapter. Model IDs are intentionally blank until chosen locally. No vendor SDK or extra requirements file is needed.

Put keys and `NPC_LLM_MODEL` in the root `.env` (see [.env.example](../../.env.example)); OS environment variables take precedence. OpenRouter reads `OPENROUTER_API_KEY`, Gemini reads `GEMINI_API_KEY`. Each can instead use the generic `NPC_LLM_API_KEY`. Never add an actual key field/value to a YAML profile. The strict loader rejects unknown fields and profiles over 16 KB.

Use `--live --config configs/providers/<profile>.yaml` with `python -m npc.runtime`. Without `--live`, that CLI uses the offline fake. Optional generic overrides are `NPC_LLM_BASE_URL` and `NPC_LLM_RESPONSE_FORMAT` (`json_object` or `none`). Another compatible endpoint can use a copied public profile with `provider: chat_completions`; compatibility still needs testing. HTTPS is required except loopback HTTP; local runtimes can use a nonsecret key placeholder if necessary.

Profile endpoints/authentication follow the official [OpenRouter chat-completion API](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion) and [Gemini OpenAI compatibility guide](https://ai.google.dev/gemini-api/docs/openai). A small [Gemini 3.1 Flash-Lite live experiment](../../docs/reviews/2026-10-31-behavior-quality-audit.md) confirmed transport/JSON compatibility for that model, with unresolved behavioral/grounding/latency gaps. A [Nemotron/OpenRouter diagnosis](../../docs/reviews/2026-11-01-openrouter-output-budget.md) reproduced reasoning exhausting the short output allowance; the profile now disables reasoning for short replies. Broader quality/latency remain unverified. See the [preview guide](../../docs/GENERATION_VALIDATION.md) for commands, budgets and limitations.

The optional `reasoning_effort` profile field (or local `NPC_LLM_REASONING_EFFORT`) accepts none/minimal/low/medium/high; omit it for providers/models without support. The Gemini profile selects minimal, as mapped by [official Gemini compatibility documentation](https://ai.google.dev/gemini-api/docs/openai/#thinking); this does not guarantee zero thinking or network latency. Changing providers/models can require a different supported setting.

OpenRouter's profile sets `reasoning_enabled: false`, sent as `reasoning: {enabled: false}`. This keeps the short output allowance available for answer text on compatible models. It is distinct from hiding reasoning text, which still consumes tokens. In a custom profile set the boolean to true or omit it to use model defaults. Do not combine it with `reasoning_effort` or the `NPC_LLM_REASONING_EFFORT` override. Models with mandatory reasoning can still exhaust the allowance; empty length-limited output reports `provider_output_limit` instead of a protocol error. Never use reasoning text as NPC speech. See [OpenRouter reasoning controls](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).

For Nemotron Lightning use the full model ID `nvidia/nemotron-3.5-lightning:free`. If a selected endpoint lacks JSON response-format support, set `NPC_LLM_RESPONSE_FORMAT=none`; prompts and response validation still require valid JSON.
