# RAG as an internal NPC component

Outcome: one NPC-main folder, one .venv and one pinned requirements.txt. Reuse the existing folder-RAG ingestion/embedding/Chroma code under src/npc/rag/backend; no standalone frontend/chat/TTS/server copied. Documents live in Knowledge base/kb and generated index/model cache in ignored data/rag. The configured local retriever calls the backend directly. Existing HTTP mode remains an explicit compatibility option, not a default dependency.

Plan: port only backend config/models/loaders/embeddings/service and its meaningful deterministic storage/loader tests; add a bounded async local adapter and shared evidence eligibility normalization; select backend in trusted RAG configuration. Add local prepare/sync/status/query commands, run prepare during project setup, and keep ingestion out of dialogue turns. Copy the owner's existing dialogue file and cached embedding artifacts without overwriting local edits; rebuild a new NPC-local index rather than editing/copying the live external database. Keep original RAG installation untouched. Add only resolver-confirmed dependency pins to the single requirements file.

Plan self-review (not independent): direct calls avoid a second launch/server while preserving component boundaries. Blocking embeddings run off the event loop; an admission gate stays held until the actual worker finishes, even if the caller times out/cancels, so there is no queued CPU-query buildup. Interactive startup must not silently download models or ingest. Use a short file-lock wait, existing final turn deadlines and source prefilter/rechecks. Default paths are anchored to NPC-main, not caller CWD or Desktop/RAG. Corpus/model cache remain ignored and no API keys/state are migrated. A fresh local index prevents stale absolute-path metadata and live-SQLite-copy hazards.

Verification: existing evidence/HTTP contract tests; deterministic real-Chroma persistence, incremental edits/deletion, failed staging recovery and loader tests; local adapter scope/filter, errors, concurrent admission and cancellation tests; end-to-end local retrieval -> prompt -> validated citations with a fake provider; setup command dispatch tests and full offline regression. pip check, local cached-model ingestion/query and launch readiness. No paid/free LLM calls: model API quota and response quality are separate from this packaging change.

Implementation self-review: local and optional HTTP retrieval share the same preselected source binding and normalized evidence checks; no permission logic was duplicated. Backend imports/model loading are lazy for the interactive adapter, and required cache/manifest checks fail unavailable rather than download/ingest in a turn. A single threading gate stays owned by native work after caller timeout/cancellation; real-store and fake-worker tests cover busy/lock/recovery behavior. Existing external data and unrelated working-tree changes were preserved. No standalone frontend/provider code was copied, no new environment created, no generated assets tracked, and no LLM request was made during migration.

Verification: focused backend/adapter/loader/setup suite: 63 passed. The actual normal setup entry point completed with pip check, runtime-media verification, local CPU model preparation, incremental indexing without errors and the full offline suite: 417 passed in 12.72 seconds. The NPC-local index has 8,297 chunks across the dialogue dump and the local README. A core retrieval -> prompt -> fake-provider -> validation smoke test from the parent directory returned model_success twice, verified original citation mapping and paths under NPC-main, and confirmed no standalone rag package installed. Approximate cold/warm end-to-end smoke times were 1,219/109 ms; two samples are not a latency benchmark or game-resource signoff. Final whitespace, documentation-link, ignore/readiness checks are included in the handoff.

Remaining limits: the change fixes component placement/deployment, not free-provider quota, raw-dialogue relevance, missing speaker/quest authorization, semantic/temporal grounding, or measured game contention. A relocated generated index retains its original absolute-path guard and should be rebuilt deliberately for that checkout; it is not silently reassigned. The original standalone installation remains available as a backup but is not a runtime dependency.
