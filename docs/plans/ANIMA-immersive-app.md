# Anima application: plan and pre-implementation self-review

2026-10-31. Backup b102c3d pushed to branch and main before work; 263 offline tests passed. Follow development/design-review skills; review is self-review plus actual browser automation, not an independent reviewer claim.

Outcome: user-facing Anima, a separate immersive companion application with a Nordic-inspired ivory/charcoal/amber visual style, close conversation framing, camera zoom/full-figure controls, bottom-centre subtitles, optional journal/immersive mode, and explicit impact/prompt inspection. Keep the existing package/data paths compatible rather than migrate saved relationships or duplicate core logic. A new apps/anima entry point provides an ASGI deployment surface; legacy local entry remains supported. run_anima.bat is primary, prior launcher forwards to it.

Online scope pending user preference: default to a private password-protected demo deployment, not an unauthenticated public multi-user product. Bind locally by default. Require explicit public origin and password for hosted mode; same-origin/token checks, secure session cookies, bounded authentication attempts/sessions, fixed assets, finite body/response limits, shared global provider admission, and per-session relationship scope are required before claiming hosting readiness. No deployment/cloud resource or private game-asset publication is authorized by this work. Hosting code must work without Skyrim/Piper. Document HTTPS/reverse proxy and single-process limits.

Prompt inspection captures the actual provider-bound packages (initial and repair), not a reconstructed approximation. No API keys/headers/raw error bodies. Authored/silent routes clearly show no LLM input. App diagnostics remain separate from core; provider wrapper and scoped per-turn capture avoid cross-session mixing. Audit persona/context-to-plan mapping with paired fixtures, and add explicit resolved recognition/trust/service duty to the prompt where currently only influence codes imply them. Do not dump excluded facts or turn player dialogue into world truth. Context truth/recall and human realism remain evaluation gates, not claims from schema validity.

Facial feasibility: installed BSA includes femalehead/malehead/eye TRI data. PyNifly documents TRI expression morph support, but current exporter freezes evaluated meshes and explicitly disables morphs, skins and animation. Reusing facial shapes requires preserving topology, transferring morph deltas to the specific FaceGen head, retaining eye/mouth components, exporting glTF morphs and driving timing. Not a drop-in easy addition; defer rather than risk broken faces or label procedural motion as native game animation. Sources: https://github.com/BadDogSkyrim/PyNifly and https://baddogskyrim.github.io/BethesdaLibrary/file-formats/morphs-shapekeys/ .

Acceptance: deterministic capture tests including repairs/no-call/isolation; paired context-to-prompt tests; camera pure-function JS unit tests; hosted authentication/session/CSRF/Host/body/admission/isolation tests with fake providers; full Python regression, JS syntax/unit checks, pip check, desktop/mobile actual-browser interaction/screenshots (model, closer framing/zoom, subtitles, inspector, immersive toggle, keyboard and no overflow). Visually review and fix findings. Browser routes may use original illustrations without private assets. No new LLM classifier/critic, no hosted TTS service or speculative agent runtime. Record remaining gates and actual results.
