# Dialogue reference attribution fix

Reproduction: the owner's two Eorlund turns were accepted with a passage containing another speaker's first-person friendship, clan/family claims and mutually exclusive alive/dead variants. A second passage contained a wife's first-person account. The model adopted those relationships as Mira's; the follow-up query then included that erroneous NPC answer. Existing evidence-ID validation does not establish semantic truth or speaker ownership.

Plan: mark the configured raw dialogue export explicitly; parse only complete tab-separated FormID records at the RAG boundary, keep source chunk IDs plus record IDs, omit first/second-person lines and conservative state-dependent variants, and label retained excerpts as unattributed archived dialogue. No rewrite of the corpus/index, invented speaker mapping, synthesized lore, model classifier, or additional retrieval pass. Ordinary reference documents remain unchanged. Follow-up query context uses prior player text only. Strengthen context policy so authored persona/observations determine personal history and previous NPC claims are not proof.

Plan self-review (not independent): filtering drops some useful statements and cannot certify truth, but prevents the demonstrated direct source transfer without inventing identities/quest state. Fail closed for partial/unrecognized export rows. Preserve provenance and whole excerpts. Keep game entity names out of runtime rules. Existing acknowledged history is retained; test a poisoned recent NPC answer against the filtered current evidence. This is deliberately narrower than speaker extraction, quest evaluation or a generic semantic validator.

Acceptance/tests: synthetic exports with mixed speakers, first-person possessives/contractions, second-person claims, state variants, chunk-boundary fragments, stable third-person references, empty eligible results and unchanged normal documents. Test source binding selection, prompt attribution rules and original question-only follow-up retrieval. Run full offline regression and bounded live original/follow-up probes including previously contaminated history. Report sample outcomes without claiming universal hallucination prevention.

Implementation review finding: filtering source passages plus an instruction was insufficient. A live poisoned-history probe still copied the old NPC claim. Resolution: dialogue-export knowledge contexts now retain prior player utterances but omit generated NPC replies from prompt history; the saved history is untouched and normal reference/no-RAG history behavior is preserved. Dialogue source kind is retained even for empty results, so missing evidence cannot re-enable the poisoned reply. Follow-up retrieval already uses player text only. Complete punctuation-terminated final record text is retained when chunking strips trailing tabs; incomplete fragments remain excluded.

Second live probe: the original question no longer borrowed friendship/allegiance with the poisoned reply omitted, but the follow-up cited an unrecognized evidence identifier. The new record labels introduced competing citation-looking IDs. Resolution: record locators stay in structured inspection metadata only; model inputs expose the existing chunk evidence ID and plain excerpt text. Prompt guidance explicitly cites retrieved_evidence.id and disallows unsupported character judgments/biography. This preserves original source mapping without introducing a second citation namespace.

Citation follow-up correction: a recorded raw candidate showed the model dropping the chunk suffix from a 64-character source revision ID. Removing record labels alone did not resolve that. Prompt-only kb1/kb2 labels now map explicitly to the whole evidence items actually packed. Response validation resolves them back to original IDs, rejects unknown/omitted targets, and avoids observation-ID collisions. The inspector includes the map; no validation bypass or source-ID guessing is used. Runtime source IDs remain unchanged. Added an end-to-end fake-provider check that reads citation labels from actual serialized messages.

Final pre-handoff validation: 372 full offline tests passed (362 before this change), including source filtering, contaminated-history omission, ordinary reference compatibility, alias/source resolution and observation collisions. Live Nemotron probes with an explicitly poisoned earlier NPC answer then returned model_success for both the original Eorlund question and ?What about him??, without adopting friendship/allegiance/death. The first reply still embellished with an unsupported popularity claim, so the two samples are not a grounding-quality signoff. Gemma 4 31B free and Xing 4.0 free comparison attempts both returned provider_rate_limited; no alternative model was selected or silently configured. Corpus, index and persisted conversation were not modified by the tests.
